# Запуск в Telegram — чек-лист

Пять шагов. Токен живёт только в двух местах на выбор: в секретах GitHub или в файле `.env`
на твоём компьютере. В файлы репозитория и в переписку он не попадает никогда.

## 1. Токен

Токен, который однажды попал в коммит `90b989b`, считается засвеченным: такие значения
автоматические сканеры собирают из публичных репозиториев за минуты.

- [ ] В [@BotFather](https://t.me/BotFather): `/revoke` → выбрать бота → получить новый токен

Дальше новый токен кладётся в одно из двух мест — выбери путь.

### Путь А — без терминала (через секреты GitHub)

Подходит, если правишь проект через сайт GitHub. Токен хранится в зашифрованном хранилище
GitHub, в файлы репозитория не попадает и в логах маскируется.

- [ ] **Settings → Secrets and variables → Actions → New repository secret**
      имя: `BOT_TOKEN`, значение: новый токен → **Add secret**

Секрет виден только раннеру во время запуска: ни в коде, ни в интерфейсе его больше не прочитать.

### Путь Б — локально (через `.env`)

Подходит, если папка проекта лежит на компьютере и есть терминал.

```bash
cp .env.example .env
nano .env          # или открыть любым редактором
```

```
BOT_TOKEN=новый_токен_от_botfather
APP_URL=https://my-body-upgrade-app.vercel.app
```

`.env` закрыт в `.gitignore` — он остаётся на твоём диске и никуда не уходит.
Файл начинается с точки, поэтому скрыт: в Finder показать его — `Cmd+Shift+.`,
в проводнике Windows — **Вид → Показать → Скрытые элементы**, в VS Code виден сразу.

Никогда не вписывай токен в `tools/setup-bot.sh`, в `.env.example`, в README или в любой другой
файл репозитория: всё, что там лежит, уходит на GitHub. И не присылай его в переписке.

## 2. Защита от повторной утечки

- [ ] На GitHub: **Settings → Code security → Push protection** — включить.
      Это работает и для правок через сайт.

Если работаешь локально, дополнительно:

```bash
git config core.hooksPath .githooks   # хук отменит коммит с секретом
./tools/check-secrets.sh --history    # проверка, что ничего не утекло
```

## 3. Мини-приложение в BotFather

Эту часть Bot API не умеет, только руками, один раз.

- [ ] `/newapp` → выбрать бота
- [ ] Название, короткое описание
- [ ] Иконка 640×360
- [ ] URL: `https://my-body-upgrade-app.vercel.app`
- [ ] Короткое имя приложения

На выходе получишь прямую ссылку вида `t.me/<бот>/<приложение>` — её можно слать кому угодно.

## 4. Настройка бота

Скрипт ставит кнопку меню, имя, описания и команды.

**Путь А (без терминала):** вкладка **Actions** → слева «Настроить бота» → **Run workflow** →
адрес приложения уже подставлен → **Run workflow**.

**Путь Б (локально):**

```bash
./tools/setup-bot.sh
```

Скрипт сам читает `.env` и вырезает токен из любого вывода. Ожидаемый результат в обоих случаях:

```
Бот:
  @твой_бот
Приложение: https://my-body-upgrade-app.vercel.app

Настраиваю:
  ok  setChatMenuButton
  ok  setMyName
  ok  setMyShortDescription
  ok  setMyDescription
  ok  setMyCommands
```

Совсем без автоматики то же самое делается руками:
`/mybots` → бот → **Bot Settings → Menu Button** → вставить адрес приложения.

## 5. Проверка

- [ ] Открыть чат с ботом, нажать кнопку меню — приложение открывается на весь экран
- [ ] Свайп вниз не закрывает приложение во время тренировки
- [ ] В профиле блок «Аккаунт Telegram» показывает твоё имя и «синхронизировано»
- [ ] Закрыть квест, потом открыть приложение с другого устройства под тем же аккаунтом —
      журнал должен подтянуться сам

Отладка на компьютере: Telegram Desktop → правый клик по мини-приложению → «Inspect».

---

Если что-то не открывается, смотри в таком порядке: адрес в BotFather начинается с `https`,
деплой на Vercel зелёный, в консоли devtools нет ошибок загрузки.
